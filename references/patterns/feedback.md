# 反馈与状态

## 原则

每个操作都有回应，只回应一次，而且尽量在发生的地方回应。

| 情况 | 回应 |
| --- | --- |
| 按下 | 按下态（填充色；触屏上缩到 .97） |
| 短等待（< 1s 左右） | 按钮里转圈，宽度不变，同时禁用 |
| 内容加载 | 静态骨架：300ms 后才出现，出现后至少保留 600ms |
| 刷新已有数据 | 保留旧数据，内容区透明度降到 60%；不清空，也不出骨架 |
| 成功，结果在屏幕上看得见 | 什么都不说 |
| 成功，结果不在眼前（导出、后台任务、发送） | `notify.success`，4s |
| 需要知道的中性信息（「同步将在后台完成」） | `notify.info`，4s |
| 完成了，但有保留（「已导出 98 条，2 条因格式问题跳过」） | `notify.warning`，6s |
| 可逆操作（归档、移出、切换） | 立即执行，`notify.undo`，8s |
| 不可逆操作 | 先 ConfirmDialog，执行后结果可见，就不再提示 |
| 字段错误 | 在字段下方显示，并把焦点移到第一个错误 |
| 区块加载失败 | 在区块里显示 `StateView kind="error"`，带「重试」 |
| 后台操作失败（不属于某个字段或区块） | `notify.error`，不自动消失，能重试时带「重试」 |
| 等你处理，但不是错误（「新版本已下载，重启后生效」） | `notify.prompt`，带一个动作，不自动消失；同一件事只留一条（同一个 id 再弹会替换） |
| 你发起的慢操作，在别处进行（下载更新、大批导出） | `notify.loading`，结束时用 id 收起，再按上面的规则反馈结果 |
| 确认框里的操作失败 | 确认框不关，在框里显示原因 |

同一件事不能既弹 Toast 又弹框。

原生 App 例外：用户操作失败（不属于某个字段或区块）可以用系统 Alert，带「重试」时放在 Alert 的按钮里，技术细节放进「详情」。web 和嵌入页不这么做。

## Toast

- 顶部居中，多条时叠放（最新的在最前，鼠标悬停时展开）；手机上在顶部、占满宽度，避开刘海安全区。最多同时显示 3 条，悬停时暂停计时。
- 浮层底（`popover` + `shadow-overlay`）。级别只用图标颜色区分：成功绿、提示蓝、警告黄、错误红；错误不会自动消失，所以再加一层 `destructive-subtle` 淡红底。
- 一句话，不加标题。尽量带上对象（「已归档 3 个项目」），不写「操作成功」。
- 不自动消失的只有三种：错误、等你处理的提示（`prompt`）、后台进度（`loading`）。页面里的等待用骨架或按钮转圈，不用 `loading`。
- 只通过 `notify` / `notify.success` / `notify.info` / `notify.warning` / `notify.undo` / `notify.error` / `notify.prompt` / `notify.loading` 调用。

## 五种数据状态

每个异步视图（列表、表格、面板、页面区块）都要处理五种状态，前四种由 `StateView` 提供：

| 状态 | 什么时候 | 显示 | 操作 |
| --- | --- | --- | --- |
| 加载中 | 首次加载、还没有数据 | 300ms 前留白，之后出骨架 | — |
| 空 | 确实还没有内容 | 「还没有项目」+ 一行说明这是什么 | 创建第一个 |
| 无匹配 | 有筛选或搜索条件，结果为 0 | 「没有符合条件的结果」 | 清除筛选 |
| 无权限 | 403 | 「你没有查看权限」+ 去找谁开通 | — |
| 出错 | 请求失败 | 「加载失败」+ 一句人话 | 重试 |

- 加载中不能显示「空」，失败也不能显示成「空」。
- 空状态才可以放插画；其余状态只放一个图标。
- 空状态出现时淡入一次，然后保持静止；错误状态始终静止。

## 乐观更新

改动低风险的数据（勾选、排序、改名）时：

1. 先改界面。
2. 失败时回滚，并用 `notify.error` 说明。
3. 不在界面上显示「保存中…」。

## 进度

- 进度未知时转圈，进度已知时显示百分比。
- 不做假进度条。
- 超过 10 秒的任务交给后台执行，完成后用 Toast 告知；进行中可以留一条 `notify.loading`。

## 无限滚动

- 只用于信息流（对话、动态）和媒体网格（图片、视频墙）；表格和其他列表分页。
- 离底部约 400px 时加载下一批（24 条左右），加载中在末尾补几块骨架，不整页转圈。
- 已有数据时加载失败：保留已加载的内容，末尾显示「加载失败，重试」；首批失败用 `StateView kind="error"`。
- 顶部写「共 N 个」，让人知道有多少。
- 筛选或搜索变化时从头加载，回到顶部。

## 上传队列

文件多、耗时长的上传用 `UploadQueuePanel` + `useUploadQueue`，用户可以边传边做别的事。

- 一个文件一行。状态词固定：等待 / 上传中 x% / 已添加 / 已存在 / 失败（重试）。
- 失败写人话（「网络中断」「文件超过 20 MB」）；能重试的带「重试」，不可能成功的（太大、格式不支持）不带。
- 进度来自真实上传；拿不到进度时转圈，不画假进度条。
- 面板在右下角（手机上贴底、全宽、避开安全区），可以折叠；默认同时传 3 个。
- 标题：进行中写「上传中 · 3/10」；结束后写结果，为 0 的项不写（「已添加 8 个，失败 1 个」）。
- 全部成功后 4 秒自动收起；还有失败时不收起。全部结束后才出现 ✕，点了清掉已完成的行。
- 还有文件在传时离开页面，先让浏览器确认（beforeunload）。
- 已存在（服务端去重）不算失败，也不重复上传；能定位到原文件时给链接。
- 拖文件到页面上传时，整页显示一个拖放区，松手后进队列；文件夹逐层展开，隐藏文件跳过。
