# 反馈与状态

## 原则

每个操作都有回应，只回应一次，而且尽量在发生的地方回应。

| 情况 | 回应 |
| --- | --- |
| 按下 | 按下态（填充色；触屏上缩到 .97） |
| 短等待（< 1s 左右） | 按钮里转圈，宽度不变，同时禁用 |
| 内容加载 | 静态骨架：300ms 后才出现，出现后至少保留 600ms |
| 刷新已有数据 | 保留旧数据，内容区透明度降到 60%；不清空，也不出骨架 |
| 成功，结果在屏幕上看得见 | 什么都不说 |
| 成功，结果不在眼前（导出、后台任务、发送） | `notify.success`，4s |
| 需要知道的中性信息（「同步将在后台完成」） | `notify.info`，4s |
| 完成了，但有保留（「已导出 98 条，2 条因格式问题跳过」） | `notify.warning`，6s |
| 可逆操作（归档、移出、切换） | 立即执行，`notify.undo`，8s |
| 不可逆操作 | 先 ConfirmDialog，执行后结果可见，就不再提示 |
| 字段错误 | 在字段下方显示，并把焦点移到第一个错误 |
| 区块加载失败 | 在区块里显示 `StateView kind="error"`，带「重试」 |
| 后台操作失败（不属于某个字段或区块） | `notify.error`，不自动消失，能重试时带「重试」 |
| 确认框里的操作失败 | 确认框不关，在框里显示原因 |

同一件事不能既弹 Toast 又弹框。

## Toast

- 顶部居中，多条时叠放（最新的在最前，鼠标悬停时展开）；手机上在顶部、占满宽度，避开刘海安全区。最多同时显示 3 条，悬停时暂停计时。
- 浮层底（`popover` + `shadow-overlay`）。级别只用图标颜色区分：成功绿、提示蓝、警告黄、错误红；错误不会自动消失，所以再加一层 `destructive-subtle` 淡红底。
- 一句话，不加标题。尽量带上对象（「已归档 3 个项目」），不写「操作成功」。
- 只通过 `notify` / `notify.success` / `notify.info` / `notify.warning` / `notify.undo` / `notify.error` 调用。

## 五种数据状态

每个异步视图（列表、表格、面板、页面区块）都要处理五种状态，前四种由 `StateView` 提供：

| 状态 | 什么时候 | 显示 | 操作 |
| --- | --- | --- | --- |
| 加载中 | 首次加载、还没有数据 | 300ms 前留白，之后出骨架 | — |
| 空 | 确实还没有内容 | 「还没有项目」+ 一行说明这是什么 | 创建第一个 |
| 无匹配 | 有筛选或搜索条件，结果为 0 | 「没有符合条件的结果」 | 清除筛选 |
| 无权限 | 403 | 「你没有查看权限」+ 去找谁开通 | — |
| 出错 | 请求失败 | 「加载失败」+ 一句人话 | 重试 |

- 加载中不能显示「空」，失败也不能显示成「空」。
- 空状态才可以放插画；其余状态只放一个图标。
- 空状态出现时淡入一次，然后保持静止；错误状态始终静止。

## 乐观更新

改动低风险的数据（勾选、排序、改名）时：

1. 先改界面。
2. 失败时回滚，并用 `notify.error` 说明。
3. 不在界面上显示「保存中…」。

## 进度

- 进度未知时转圈，进度已知时显示百分比。
- 不做假进度条。
- 超过 10 秒的任务交给后台执行，完成后用 Toast 告知。
