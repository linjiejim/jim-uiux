# 文案

## 总则

- 短：按钮 ≤ 6 个字，提示一句话，说明一行。
- 直接：先说结果或动作，再说原因。
- 说人话：不用错误码、内部 ID、枚举值、技术名词。
- 一致：同一个概念在整个产品里只用一个词（比如「项目」，就不要再出现「工程」）。

## 按钮与菜单

- 写动词加对象：「新建项目」「保存修改」「删除 3 个文件」「导出 CSV」。
- 不写「确定」「提交」「OK」「是」。
- 确认框里的确认按钮，要重复标题里的动词：标题是「删除项目『官网改版』？」，按钮就是「删除项目」。
- 取消就写「取消」。在放弃修改的确认框里，两个按钮写「继续编辑」和「放弃修改」。

## 标题

- 页面标题用名词：「项目」「设置」，不写「项目管理页面」。
- 弹框标题写成动作：「新建项目」「编辑成员」。确认框的标题写成问句。
- 页面标题下不写解释句。

## 提示与反馈

| 场景 | 写法 | 不写 |
| --- | --- | --- |
| 成功 | 已归档 3 个项目 | 操作成功！ |
| 撤销 | 已删除「官网改版」· 撤销 | 删除成功，点击此处撤销 |
| 错误 | 同步失败，网络连接中断 | Error 500: ECONNRESET |
| 表单错误 | 邮箱格式不对，例如 name@example.com | 格式错误 |
| 空 | 还没有项目 + 一句说明它是什么 | 暂无数据 |
| 无匹配 | 没有符合条件的结果 | 暂无数据 |
| 无权限 | 你没有查看权限。需要权限时，请联系管理员。 | 403 Forbidden |

- 不用感叹号，不写「请」字开头的长句，不用「亲」。
- 错误要说下一步怎么做（「请重试」「检查网络后重试」「联系管理员」）。

## 状态词表

每个项目定一张固定的表，写进 `docs/DESIGN.md`。表里每个状态对应一种颜色，全产品通用。比如：

| 词 | 色调 |
| --- | --- |
| 草稿、已归档 | neutral |
| 进行中、同步中 | info |
| 待审核、需处理 | warning |
| 已完成、在线 | success |
| 失败、受阻、离线（异常时） | danger |

## 格式

- 中文与英文、中文与数字之间加一个空格：「共 57 条」「Inter 字体」。数字与单位之间不加空格：「44px」「85%」。
- 用全角中文标点；书名号或引号用「」。
- 日期：
  - 今年的写「10月31日 09:00」，跨年的写「2025年10月31日」。
  - 相对时间（「3 分钟前」）只用在动态流里，悬停时显示完整时间。
- 金额写「¥128,000」，千分位用逗号；数字用等宽数字，并且右对齐。
- 数量：「3 个项目」「共 57 条」「已选 2 项」。

## 国际化

- 所有可见文字都走 i18n。组件内置的文案在 `lib/strings.ts`，用 `configureStrings()` 替换。
- 给其他语言留出 30% 的宽度余量：按钮不写死宽度，表格列允许截断。
